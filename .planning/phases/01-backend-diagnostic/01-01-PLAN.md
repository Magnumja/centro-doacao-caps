# Plan 01: Finalize Backend Diagnostic Package

<objective>

Finalize Phase 1 as a documentation-only backend diagnostic package. The executor must verify that the current backend structure, risks, validation signals and user decisions are captured clearly enough for later implementation phases, without modifying backend implementation files.

</objective>

<scope>

## In Scope

- Validate that `.planning/backend/ANALYSIS.md` reflects the current backend structure under `server/`.
- Validate that `.planning/backend/IMPROVEMENT_PLAN.md` reflects the user decisions captured in `01-CONTEXT.md`.
- Update planning artifacts only if they drift from the current code or captured decisions.
- Run backend validation commands and record results in the plan summary.
- Produce `.planning/phases/01-backend-diagnostic/01-01-SUMMARY.md`.

## Out of Scope

- No edits to `server/**`.
- No edits to frontend source under `src/**`.
- No Prisma schema or migration changes.
- No auth/security/JWT/cookie behavior changes.
- No route/controller/service/repository refactor in this phase.

</scope>

<must_haves>

## Truths From Context

- D-01: The next implementation plan should prioritize backend organization before security hardening or deploy cleanup.
- D-02: The target backend pattern is `route -> controller -> service -> repository` for all backend domains.
- D-04: The first refactor should avoid sensitive security and Prisma files.
- D-05: Do not modify `auth`, `middleware/auth`, `config/security`, `lib/jwt`, session cookie behavior, `schema.prisma` or migrations in the first refactor.
- D-07: Require route-level contract tests as the main safety net for refactors.
- D-09: Public donations need anti-spam mitigation planning.
- D-10: PII handling needs a minimum retention posture.
- D-12: Prisma schema and migrations remain frozen for the first implementation cycle.
- D-14: Protected/admin lists that can grow should be paginated now, especially `residents`.
- D-16: Production deploy is more important than local Docker setup in this cycle.
- D-17: In-memory `highlights` and `telemetry` behavior is accepted for now with documentation.

</must_haves>
