## Directory Purposes

**Root frontend source:**
- Purpose: Browser application source and route composition.
- Contains: React components, pages, services, hooks, CSS, typed data models, static asset imports.
- Key files: `src/main.tsx`, `src/app/router.tsx`, `src/lib/api.ts`, `src/types/index.ts`

**`src/app/`:**
- Purpose: Route table for the hash-based SPA.
- Contains: Router component and route declarations.
- Key files: `src/app/router.tsx`

**`src/pages/`:**
- Purpose: Route-level public pages that own page state and workflow orchestration.
- Contains: `src/pages/Home.tsx`, `src/pages/CapsPage.tsx`, `src/pages/Donate.tsx`, `src/pages/AboutProject.tsx`, `src/pages/YourDonations.tsx`, `src/pages/Thanks.tsx`
- Key files: `src/pages/Home.tsx`, `src/pages/CapsPage.tsx`, `src/pages/Donate.tsx`

**`src/pages/admin/`:**
- Purpose: Admin route-level pages.
- Contains: Login page and dashboard page.
- Key files: `src/pages/admin/Login.tsx`, `src/pages/admin/Dashboard.tsx`

**`src/components/`:**
- Purpose: Reusable UI components shared by public and admin pages.
- Contains: Layout, cards, badges, map, ranking, dashboard summary, count-up stats.
- Key files: `src/components/Layout.tsx`, `src/components/DonationRequestCard.tsx`, `src/components/CapsCard.tsx`, `src/components/CapsMap.tsx`, `src/components/AdminDashboard.tsx`

**`src/components/ui/`:**
- Purpose: Lower-level reusable UI pieces.
- Contains: Carousel and skeleton components.
- Key files: `src/components/ui/NewsCarousel.tsx`, `src/components/ui/Skeletons.tsx`

**`src/services/`:**
- Purpose: Frontend service adapters for backend APIs and browser-local persistence.
- Contains: Auth, dashboard, donation, needs, units, highlights, telemetry, and donor-intention services.
- Key files: `src/services/auth-service.ts`, `src/services/dashboard-service.ts`, `src/services/donations-service.ts`, `src/services/needs-service.ts`, `src/services/units-service.ts`, `src/services/donor-intentions-service.ts`

**`src/lib/`:**
- Purpose: Shared frontend helpers that are not tied to a single route.
- Contains: API client, auth bypass helper, contact URL helpers, public needs fallback helper, performance metrics.
- Key files: `src/lib/api.ts`, `src/lib/auth.ts`, `src/lib/contact.ts`, `src/lib/needs.ts`, `src/lib/performance-metrics.ts`

**`src/hooks/`:**
- Purpose: Reusable stateful frontend workflows.

**`src/data/`:**
- Purpose: Static frontend data and public fallback/mock collections.
- Contains: CAPS units, needs, hosts, donations, residents, highlight seed data, aggregate stats.
- Key files: `src/data/mockData.ts`, `src/data/mock.ts`, `src/data/highlights.ts`

**`src/types/`:**
- Purpose: Frontend TypeScript domain shapes and asset declarations.
- Contains: Core app types, dashboard-specific types, image module declarations.
- Key files: `src/types/index.ts`, `src/types/dashboard.ts`, `src/types/assets.d.ts`

**`src/Styles/`:**

- Contains: Page and layout styles with PascalCase filenames matching page/component areas.

**`src/public/`:**

## Naming Conventions

**Files:**
- Route pages use PascalCase component filenames in `src/pages/`, such as `src/pages/Home.tsx`, `src/pages/CapsPage.tsx`, and `src/pages/Donate.tsx`.
- Admin pages use PascalCase filenames inside `src/pages/admin/`, such as `src/pages/admin/Login.tsx` and `src/pages/admin/Dashboard.tsx`.
- Shared React components use PascalCase filenames in `src/components/`, such as `src/components/Layout.tsx`, `src/components/CapsCard.tsx`, and `src/components/DonationRequestCard.tsx`.
- Hooks use `use*.ts` camelCase filenames in `src/hooks/`, such as `src/hooks/useAdminLogin.ts` and `src/hooks/useDashboardData.ts`.
- Frontend service adapters use kebab-case `*-service.ts` filenames in `src/services/`, such as `src/services/needs-service.ts` and `src/services/donations-service.ts`.
- Frontend helper libraries use concise lowercase names in `src/lib/`, such as `src/lib/api.ts`, `src/lib/auth.ts`, `src/lib/contact.ts`, and `src/lib/needs.ts`.
- Frontend CSS files in `src/Styles/` use PascalCase area names matching pages/components, such as `src/Styles/Home.css` and `src/Styles/Dashboard.css`.
- Backend routes use lowercase resource names in `server/src/routes/`, such as `server/src/routes/needs.ts` and `server/src/routes/donations.ts`.
- Backend controllers, services, repositories, middleware helpers, and error classes use kebab-case filenames, such as `server/src/controllers/needs-controller.ts`, `server/src/services/needs-service.ts`, `server/src/repositories/needs-repository.ts`, `server/src/middleware/error-handler.ts`, and `server/src/errors/app-error.ts`.
- Backend tests use `*.test.ts` beside the tested service in `server/src/services/`, such as `server/src/services/needs-service.test.ts`.

**Directories:**
- Frontend feature categories are grouped by role under `src/pages/`, `src/components/`, `src/services/`, `src/hooks/`, `src/lib/`, `src/data/`, and `src/types/`.
- Admin-only frontend routes live under `src/pages/admin/`.
- Backend source is grouped by Express/API role under `server/src/routes/`, `server/src/controllers/`, `server/src/services/`, `server/src/repositories/`, `server/src/middleware/`, `server/src/config/`, `server/src/lib/`, `server/src/errors/`, and `server/src/utils/`.
- Database schema and migrations live only under `server/prisma/`.

## Where to Add New Code

**New Public Frontend Page:**
- Primary code: Add the route component in `src/pages/`.
- Route registration: Add a `<Route>` in `src/app/router.tsx`.
- Shared shell: Use the existing parent `Layout` from `src/components/Layout.tsx`.
- Styles: Add or extend a CSS file in `src/Styles/`.
- Data access: Add typed API functions in `src/services/` or `src/lib/` and call them from the page.

**New Admin Frontend Page/Tab:**
- Primary code: Extend `src/pages/admin/Dashboard.tsx` for dashboard tabs, or add a new page under `src/pages/admin/` for distinct routes.
- Route registration: Add admin routes in `src/app/router.tsx`.
- Auth/bootstrap: Reuse `src/hooks/useAdminLogin.ts` and `src/hooks/useDashboardData.ts` patterns.
- API access: Add service functions under `src/services/`, backed by protected backend routes.

**New Reusable Component:**
- Implementation: Add PascalCase `.tsx` files under `src/components/`.
- Small generic UI: Add under `src/components/ui/`.
- Types: Prefer local prop types in the component file; add shared domain types to `src/types/index.ts` or `src/types/dashboard.ts` only when reused across files.
- Styles: Use existing CSS area files in `src/Styles/` unless the codebase adds a component-specific CSS convention.

**New Frontend API Adapter:**
- Implementation: Add or extend `src/services/*-service.ts`.
- Shared HTTP behavior: Use `src/lib/api.ts`; do not call raw `fetch` for app API endpoints from pages.
- Normalization helpers: Put cross-page transformations in the service file or `src/lib/`.
- Fallback public data: Use `src/data/mockData.ts` only for public/demo fallback workflows.

**New Browser-Local Feature:**
- Implementation: Add a service in `src/services/` when the state is a browser persistence detail, following `src/services/donor-intentions-service.ts`.
- UI usage: Keep page components focused on rendering and user actions.
- Storage: Guard browser APIs when code can run outside the browser, as in `src/lib/auth.ts`.

**New Backend Resource With Simple Read-Only Data:**
- Route: Add `server/src/routes/<resource>.ts`.
- App mount: Mount it in `server/src/app.ts`.
- Persistence: Use `server/src/lib/prisma.ts` directly only when the route remains simple, similar to `server/src/routes/units.ts`.
- Validation: Use Zod in the route file when payloads are small and route-local, similar to `server/src/routes/residents.ts`.

**New Backend Resource With Business Rules:**
- Route: Add `server/src/routes/<resource>.ts`.
- Controller: Add `server/src/controllers/<resource>-controller.ts`.
- Service: Add `server/src/services/<resource>-service.ts`.
- Repository: Add `server/src/repositories/<resource>-repository.ts`.
- App mount: Add `app.use('/api/<resource>', router)` in `server/src/app.ts`.
- Tests: Add `server/src/services/<resource>-service.test.ts`.
- Pattern: Follow `server/src/routes/needs.ts`, `server/src/controllers/needs-controller.ts`, `server/src/services/needs-service.ts`, and `server/src/repositories/needs-repository.ts`.

**New Protected Backend Mutation:**
- Auth guard: Use `requireAuth` from `server/src/middleware/auth.ts` for host-scoped operations.
- Admin guard: Use `requireAdmin` from `server/src/middleware/auth.ts` for admin-only operations.
- Ownership checks: Enforce `unitId` ownership in service or route logic, as in `server/src/services/needs-service.ts`, `server/src/services/donations-service.ts`, and `server/src/routes/residents.ts`.
- CSRF/origin: Rely on global unsafe-method checks in `server/src/config/security.ts` and `server/src/app.ts`.

**New Database Model:**
- Schema: Add models/enums/indexes to `server/prisma/schema.prisma`.
- Migration: Create migrations under `server/prisma/migrations/`.
- Client access: Use the singleton Prisma client from `server/src/lib/prisma.ts`.
- Repository: Add a repository under `server/src/repositories/` when access patterns are reused or business logic is non-trivial.
- Seed data: Extend `server/src/prisma/seed.ts` when the model needs default local/demo records.

**New Backend Configuration:**
- Validation: Add checks to `server/src/config/env.ts`.
- Security request behavior: Add request policies to `server/src/config/security.ts`.
- Environment documentation: Update `server/.env.example` without adding real secrets.

**New Static Asset:**
- Public URL asset: Put files under `public/` when referenced by root-relative URL such as `/capsmargarida.jpg`.
- Imported module asset: Put files under `src/public/` when imported from TypeScript such as `src/data/mockData.ts`.
- Layout/nav assets: Check current uses in `src/components/Layout.tsx` before adding duplicates.

**New Tests:**
- Backend service tests: Add `*.test.ts` next to service files in `server/src/services/`.
- API smoke tests: Extend `server/scripts/test-api.ts` when the goal is endpoint-level verification.
- Frontend tests: Not currently detected; introduce a frontend test runner and convention before adding frontend test files.
